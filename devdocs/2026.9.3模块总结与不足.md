# 校园社区 · 模块总结 / 队员不足复盘

> 撰写对象：PM 交接复盘。基于四个功能分支合并后的一次全量统一与修复（`postingweb`）。
> 每个模块列出：【当前状态】【本次修改】【该模块队员的不足 / 违反的约定】。

---

## 0. 总览：合并后暴露的核心问题

四名队员的功能在合并时，**只有各自分支内的 `routes/*.js` 是各自写完并合入的**，但公共入口 `server/server.js` 被"帖子组"的旧版整文件覆盖，导致：

- 真正符合契约的后端模块（auth / comments / interactions / records）**根本没有被挂载**，等于白写。
- 上了一套**违反契约**的帖子实现（`server/src/`），字段、返回格式全不对。
- 前端 `vite.config.js` 只代理 `/posts` 和 `/upload`，**没代理 `/api`**，所有走统一封装的前端请求都连不上后端。
- 前后端各自残留一套重复的请求封装（`api/request.js` 与 `utils/request.js`）。

因此本次修复的本质是：**把契约（`devdocs/*`）重新立起来，删掉不合规与无用残余，补齐缺失模块。**

## 1. 后端框架 / 入口（server）

### 当前状态
✅ 已重建。

### 本次修改
- 重写 `server/server.js`：
  - 顶部 `require('dotenv').config()`，否则 `.env` 里的 `DB_*` / `JWT_SECRET` 读不到（此前完全没加载）。
  - **自动加载 `routes/*.js` 并挂到 `/api`**，符合 `AGENTS.md` 约定（加新模块不需要改本文件）。
  - 统一 404 处理（返回 `{code:1004...}`）与统一错误处理（异步异常落到 5000）。
  - 删除 `/api/hello` 测试接口。
- `server/package.json`：补上缺失的 `bcryptjs`、`jsonwebtoken`（auth 要用的依赖居然不在依赖里，之前是启动即 `MODULE_NOT_FOUND`）。

### 队员的不足
- **帖子组同学（feature/post）把公共入口整个替换成了自己分支的临时写法**，覆盖了 PM 已写好的"自动加载 routes/ 到 /api"骨架，这是本次最大的不协调根源。
- 新手常见的"为了自己能跑起来，就改公共文件"问题：没有遵守"**路由文件即可，别动 server.js / main.js 等公共入口**"的约定。
- 依赖管理不规范：用到 `bcryptjs`/`jsonwebtoken` 却没写进 `package.json`。

## 2. 认证模块 Auth（feature/login）

### 当前状态
✅ 基本合格，做一致性微调。

### 本次修改
- `routes/auth.js` 增加 `GET /users/:id`（用户公开信息，返回 id/nickname/avatarUrl/bio/postCount）。
- `toUser()` 中的 `id` 统一 `Number()`：PostgreSQL 的 `BIGINT` 主键返回是字符串，契约要求是 number（避免前后端走不齐）。

### 队员的不足
- 整体很规范（参数化查询、bcrypt、JWT、`ok/fail` 统一返回都做对了），是**全队参考实现**，基本无可指摘。
- 小瑕疵：BIGINT 的 `id` 直接 `row.id` 返回字符串，与契约里 `id: 1` 这种 number 不一致（已补）。
- 前端 `LoginView` 是合格的（走统一封装、校验、存 token）。

## 3. 帖子模块 Posts（feature/post）★问题最多

### 当前状态
🔴 **原本完全缺失（契约版），只剩一套违规实现；本次补齐。**

### 本次修改
- 删除整套不合规的 `server/src/`（`routes/postRoutes.js` / `controllers` / `models` / `db`）。
- 新建 `routes/posts.js`（契约版）：
  - `GET /posts`：分页 + 分类/标签/关键词筛选 + `new/hot` 排序，返回 `{list,total,page,pageSize}`。
  - `GET /posts/:id`：详情（含 content / isLiked / isFavorite）。
  - `POST /posts`：发布（事务内插帖子 + 标签 upsert + 关联）。
  - `PUT /posts/:id`：作者可编辑（软改 + 重绑标签）。
  - `DELETE /posts/:id`：软删除（作者或 admin）。
- 前端重写 `views/PostsView.vue` 与 `views/WritePostView.vue`（见第 9 节）。

### 队员的不足（违反约定最多）
- **返回格式错误**：用 `{ code: 200, msg: '...' }`，契约是 `{ code: 0, message, data }`；成功的 `code` 应为 `0`，不是 `200`。
- **字段名凭感觉**：用 `categoryid` / `tag` / `authorid`，契约是 `categoryId` / `tags` / 鉴权后取当前用户。
- **不挂认证**：发帖/编辑/删除都没做"必须登录/仅作者"校验，任何人能改任意帖子。
- **不存在标签多对多**：把标签塞在一个 `tag` 字段里，没维护 `post_tags` / `tags` 表。
- **列名错误**：用 `posts.create_time / update_time`，表结构是 `created_at / updated_at`，直接 `SELECT *` 导致列对不上。
- **不做计数维护**：软删除等未同步 `*_count`（违反"写操作同一事务更新冗余计数"约定）。
- **前端直接在页面写 `axios.get('http://127.0.0.1:3000/posts')`**：违反"页面禁止直接 axios/fetch、必须走 `src/api/`"；写死了后端地址；还用 `res.data.data` 这种假设 `{code:200}` 的取值。
- **样式写死色值**：`#f5f7fa / #303133 / #606266 ...`，违反"只用 `tokens.css` 变量"。
- **`services` 概念不明**：把标准请求封装复制了一份 `utils/request.js`，与 PM 的 `api/request.js` 重复。

## 4. 评论模块 Comments（feature/comment）

### 当前状态
✅ 已合格，仅格式化。

### 本次修改
- 仅用 prettier 统一代码风格，逻辑未动。

### 队员的不足
- 质量高：越权判断、楼中楼校验、事务维护 `comment_count`、软删除、`GREATEST` 防负数都做对了。
- 小瑕疵：评论点赞（`POST/DELETE /comments/:id/like`）当时没做，已在 **互动模块** 里实现（其实该接口在 `interactions.js`，模块边界略有交叉——评论点赞放互动模块是合理的）。
- 代码偏长/重复（很多 `parsePage`、`toXxx` 函数在多文件复制），会导致后续维护成本，可考虑抽公共工具，但本次为保持"面向新手、别炫技"未动。

## 5. 互动模块 Interactions（feature/interaction）

### 当前状态
✅ 已合格，仅格式化。

### 本次修改
- 仅 prettier 格式化（原文件缩进/换行较乱）。
- 经冒烟测试确认帖子点赞/取消、收藏/取消、评论点赞/取消均返回契约结构 `{liked,likeCount}` / `{isFavorite,favoriteCount}`。

### 队员的不足
- 功能与契约一致，但**风格与其他模块不统一**：
  - 用了 `{ notFound: true }` 这样的内部标记 + `next(err)` 错误转发，而 auth/comments 是直接 `return fail(...)`。风格不统一会增加同学互读负担。
  - 抽了 `withTransaction`/`ensurePostExists` 等辅助函数，方向对，但 `getPostCount(client, postId, countField)` 用了模板字符串拼列名 `SELECT ${countField}`，有轻微 SQL 注入面（列名来自内部常量，风险低，但写法不严谨）。
  - 部分换行缩进不整齐（已格式化）。

## 8. 上传功能 Upload（保留但规范化）

### 当前状态
✅ 保留并规范化（按你的选择：保留）。

### 本次修改
- `server.js` 中的 `/api/upload`：返回统一格式 `{ code: 0, message, data: { url } }`；失败用 `{ code:1001, data:null }`（原来是 `{code:200}` / `{code:400,msg}`）。

- 前端写死后端地址、在页面直接 axios。
- 遗留无用的 `utils/upload-state.js` 及测试（未在本次保留，已删）。
