# 账号绑定与密码安全设计

## 目标

在现有用户名认证基础上，增加真实手机号/邮箱绑定、使用已绑定手机号或邮箱加密码登录、登录后修改密码，以及通过绑定联系方式找回密码的完整链路。功能只扩展认证模块，不重新启用分类、评论、点赞、收藏或推荐功能。

## 范围

### 包含

- 绑定手机号：发送真实短信验证码，校验后写入当前用户的唯一手机号。
- 绑定邮箱：通过 SMTP 发送真实邮件验证码，校验后写入当前用户的唯一邮箱。
- 登录标识：`username`、已绑定 `phone`、已绑定 `email` 均可配合密码登录。
- 修改密码：已登录用户提交旧密码和新密码，成功后签发新 JWT。
- 找回密码：使用已绑定手机号或邮箱接收验证码，验证后重置密码。
- 个人中心展示脱敏的手机号/邮箱绑定状态。

### 不包含

- 短信验证码登录、第三方 OAuth、换绑前的多设备会话管理。
- 真实生产密钥、短信签名/模板内容；这些通过 `.env` 和服务商控制台配置。

## 推荐架构

后端使用两个可替换的通知适配器：`sms-provider.js` 调用阿里云短信 SDK，`email-provider.js` 使用 Nodemailer SMTP。验证码业务只依赖 `sendCode(channel, target, code, purpose)` 接口，因此测试可以注入内存假发送器，不会产生真实费用。

数据库在 `users` 增加 `phone` 唯一字段，并新增 `verification_codes` 表保存 `user_id`、渠道、目标地址、用途、验证码哈希、过期时间、尝试次数、消费时间及时间戳。验证码只保存哈希，不保存明文。

## 接口

- `POST /api/auth/contact/send-code`：需登录；请求 `{ channel: "phone"|"email", target }`，用途固定为绑定；返回发送成功信息。
- `POST /api/auth/contact/bind`：需登录；请求 `{ channel, target, code }`，校验成功后更新联系方式。
- `POST /api/auth/password/change`：需登录；请求 `{ currentPassword, newPassword }`，返回新 token 和用户信息。
- `POST /api/auth/password/reset/send-code`：无需登录；请求 `{ channel, target }`，对不存在或未绑定目标也返回统一成功文案，防止枚举账号。
- `POST /api/auth/password/reset`：无需登录；请求 `{ channel, target, code, newPassword }`，重置后返回登录所需结果。
- `POST /api/auth/login`：请求字段改为 `{ identifier, password }`，兼容旧字段 `username`；按用户名、手机号或邮箱查找用户。
- `GET /api/auth/me`：增加 `phone`、`email` 的脱敏值及 `phoneBound`、`emailBound`。

## 验证码规则

- 使用密码学安全随机数生成 6 位数字验证码，5 分钟有效。
- 同一渠道和目标 60 秒内不可重复发送；发送新验证码会使旧验证码失效。
- 单个验证码最多验证 5 次，成功后立即消费。
- 邮箱统一小写并去除首尾空格；手机号按中国大陆 `1` 开头的 11 位格式校验。
- 绑定时要求当前登录用户；目标已被其他账号占用返回冲突错误。

## 前端交互

在 `ProfileView.vue` 增加账号安全区域：显示脱敏联系方式、绑定表单、验证码倒计时、修改密码表单和找回密码入口。`LoginView.vue` 将登录输入改为“用户名 / 手机号 / 邮箱”，保留原有用户名登录兼容。所有请求继续通过 `client/src/api/auth.js` 和统一 request 封装。

## 错误处理

沿用 `{ code, message, data }` 响应格式。参数格式错误使用 `1001`，未登录使用 `1002`，联系方式冲突使用 `1005`，验证码无效/过期使用 `1001`；服务商失败记录服务端日志并返回通用错误，不暴露密钥和供应商细节。

## 测试策略

- 先为规范化、验证码生成/过期/尝试次数、手机号邮箱登录标识解析、密码修改和重置流程编写失败测试。
- 使用注入的假短信/邮件发送器断言调用参数，不向真实服务商发送测试消息。
- 增加路由层数据库查询契约测试，覆盖未登录、冲突、错误验证码和成功响应。
- 前端测试覆盖登录占位文案、绑定表单倒计时、修改密码表单和脱敏展示。
- 最终运行后端 `npm test`、前端 `node --test test/*.test.js`、`npm run lint`、`npm run build`。
