# 首页帖子入口与页脚设计

## 目标

在 `update` 分支中接入 `develop` 已完成的帖子模块，并把首页改成可直接浏览内容的入口，同时补齐 GitHub、团队联系和帮助反馈入口。现有用户名登录、手机号/邮箱绑定、验证码和修改密码能力必须保持不变。

## 范围

- 合入帖子广场、帖子详情、发帖、分类和推荐/热门/最新排序相关的前后端代码。
- 首页保留社区欢迎区，并新增“推荐 / 热门 / 最新”内容切换区。
- 页脚使用全宽深色区域，提供仓库链接、团队邮箱和帮助/建议/投诉邮箱。
- 推荐排序只复用 `develop` 已有接口，不新增推荐算法。
- 不实现评论、点赞、收藏逻辑；这些交互如果由 `develop` 页面显示，保持接口兼容但不扩展本次范围。

## 关键决策

1. 以 `update` 当前认证实现为准解决合并冲突，不能用 `develop` 的旧 `auth.js`、认证 API 或用户资料结构覆盖它。
2. 首页调用现有 `getPostList({ rank })` 接口。`recommend` 需要登录；未登录时显示明确的登录入口和错误提示。
3. GitHub 链接指向 `https://github.com/YangKunYi24320314/postingweb`。
4. 团队联系和帮助/建议/投诉统一使用 `205613196@qq.com` 的 `mailto:` 链接。
5. 页脚不使用嵌套卡片，移动端改为单列布局，所有链接均可键盘聚焦。

## 验收标准

- `update` 分支可启动前后端，登录账号 `111 / 123456` 仍能登录。
- 首页可切换推荐、热门、最新，并展示帖子列表或可理解的空状态。
- 帖子广场、帖子详情、发帖和分类路由可访问。
- 页脚 GitHub、团队邮箱、帮助/建议/投诉链接真实可点击。
- 前端 lint/build 通过，后端测试通过，浏览器验证首页和登录流程。
