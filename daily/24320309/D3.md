# D3 日报 

## 今日目标
围绕用户登录认证模块进行后端接口开发，基于 PostgreSQL 完善用户数据表设计。完成用户个人信息相关的基础功能，实现登录后获取自身信息、修改资料、查看他人公开资料，同时开发绑定邮箱、手机号与修改密码接口；搭建好路由、控制器、中间件的项目分层结构，将代码提交至对应的功能分支。
## 实际进展
1. 完成**获取当前登录用户信息**接口，通过 JWT 鉴权中间件从 token 解析出用户 ID，查询数据库返回当前登录用户的基础资料，对敏感字段如密码进行过滤，不会返回至前端。
2. 开发**更新个人信息**接口，登录用户可修改昵称、头像等公开资料；添加参数校验，过滤非法字符，仅允许用户修改自身账号的数据。
3. 实现**查看某用户公开信息**接口，支持根据用户 id 查询他人对外展示资料，对手机号、邮箱等隐私字段做隐藏处理，保证用户隐私安全。
4. 新增**绑定邮箱、绑定手机号**两项功能接口，校验邮箱与手机号格式，数据库检查该联系方式是否已经被其他账号占用，避免重复绑定。
5. 开发**修改密码**接口，增加旧密码校验逻辑，使用 bcrypt 将输入的旧密码和数据库加密密码比对；修改成功后对新密码重新加密再存入数据库。
6. 整理今日所有接口路由，统一划分到认证模块路由下，将全部代码提交推送至 GitHub `feature/login` 开发分支。
## 遇到的问题与解决
1. 后端接口调用出现跨域报错，浏览器拦截了请求。一开始尝试手动设置响应头，配置繁琐；后续查阅资料，引入 cors 中间件，在项目入口文件全局开启跨域配置，成功解决跨域访问问题。
2. 修改密码接口调试一直返回密码比对失败。经过一步步打印日志排查，发现更新密码时没有对新密码执行 bcrypt 加密就直接入库，导致后续校验永远无法匹配；补上加密处理逻辑之后，接口调试正常通过。
3. 查询用户公开信息时不小心把手机号、邮箱等隐私字段返回前端。通过修改 SQL 查询语句，指定查询字段，过滤掉隐私信息，完成隐私权限控制。
