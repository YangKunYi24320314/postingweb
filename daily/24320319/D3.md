# D3 日报

## 今日目标

今天计划在已有校园论坛项目基础上继续完善帖子广场功能，增加最新，最热，为你推荐筛选，重点完成推荐与排序相关能力。具体目标包括：从 `develop` 分支同步队友新完成的帖子详情页和附件功能，解决与自己 `feature/recommendation` 分支之间的合并冲突；优化帖子广场的分类与标签设计，使分类更贴合校园论坛场景；实现“最新、热门、猜你喜欢”可以组合选择的排序逻辑；补充测试数据，用于验证热门排序和个性化推荐是否能体现差异。

## 实际进展

1. 在 `feature/recommendation` 分支完成推荐与排序模块开发。
2. 将帖子分类从原来的“随便聊聊、学习交流、二手交易”等调整为更适合校园社区的频道，包括“课程学业、校园生活、社团活动、二手闲置、求助问答、组队搭子、校园资讯、经验分享”。
3. 调整标签设计，将 tag 定位为帖子内部的话题关键词，而不是帖子广场顶部的固定筛选栏。帖子列表中仍然展示每篇帖子的 tag，点击 tag 后会自动按该 tag 搜索。
4. 后端 `GET /api/posts` 新增 `rank` 组合排序参数，支持 `latest`、`hot`、`recommend` 多个排序因子组合使用。
5. 实现热门排序公式：`浏览数*1 + 点赞数*3 + 收藏数*4 + 评论数*5`。
6. 实现猜你喜欢排序逻辑：根据用户浏览、点赞、收藏过的帖子标签计算兴趣权重，其中浏览权重为 1，点赞权重为 3，收藏权重为 4。
7. 处理推荐冷启动问题：如果用户还没有浏览、点赞、收藏行为，选择“猜你喜欢”时先使用热门分进行兜底排序，避免推荐列表没有明显效果。
8. 与 `develop` 分支合并，保留队友新增的帖子详情页、评论组件和附件上传功能，同时保留自己的帖子广场推荐排序逻辑。
9. 新增 `devdocs/sample_posts_seed.sql`，用于生成测试用户、测试帖子、分类、标签、评论、点赞、收藏和浏览记录，方便验证推荐与热门排序。
10. 排查帖子详情页 500 错误，发现原因是本地 PostgreSQL 缺少队友新增的 `post_attachments` 表，而不是评论数据缺失。

## 遇到的问题与解决

1. **推荐排序和热门排序如何同时生效**

   一开始考虑把“最新、热门、猜你喜欢”做成单选，但这样无法表达“既符合兴趣又比较热门”的场景。后来改成组合排序，前端传 `rank=latest,hot,recommend`，后端分别计算时间新鲜度分、互动热度分和兴趣匹配分，再把多个分数相加后排序。这样用户可以单独看热门，也可以看“热门 + 猜猜你喜欢”的综合结果。

2. **猜你喜欢在没有用户行为时无法推荐**

   推荐算法依赖用户历史行为，如果用户刚注册，没有浏览、点赞、收藏记录，就无法计算标签偏好。解决方式是增加冷启动兜底：当用户没有偏好数据时，`recommend` 暂时使用热门分排序；当用户产生行为后，再根据标签偏好计算推荐分。

3. **合并 `develop` 后出现多个冲突**

   队友在 `develop` 中新增了帖子详情页、附件上传和评论相关功能，而自己也修改了 `PostsView.vue`、`post.js`、`posts.js` 和接口文档，因此合并时出现冲突。解决时保留队友的详情页、附件接口和路由能力，同时把自己的分类频道、tag 点击搜索和 `rank` 排序逻辑重新合入，最终保证两个功能可以共存。

4. **帖子详情页点击后返回 500**

   前端控制台只显示 `/api/posts/:id` 返回 500，最开始容易误以为是没有评论数据。后来查看后端接口逻辑，发现帖子详情会查询 `post_attachments` 表，而本地数据库还没有该表。解决方式是在 PostgreSQL 中补建 `post_attachments` 表和对应索引，使详情页接口可以正常查询附件数据。
