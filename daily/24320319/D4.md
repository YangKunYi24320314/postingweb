## 遇到的问题与解决

1. **推荐算法只计算行为类型，没有考虑行为发生时间**  
   原来的推荐算法会读取浏览、点赞、收藏三类行为，但旧行为和新行为的影响差不多。这样会导致用户很久以前感兴趣的内容仍然长期影响推荐结果。解决时在 SQL 中根据 `histories.viewed_at`、`post_likes.created_at`、`favorites.created_at` 计算时间衰退系数，再乘以原来的基础权重，使推荐更贴近用户近期兴趣。

2. **详情页点击 tag 后不能进入对应搜索结果**  
   帖子广场里的 tag 可以点击搜索，但详情页的 tag 只是普通标签，没有绑定点击事件。解决方式是在详情页增加 `searchByTag` 方法，通过路由跳转到帖子广场，并把 tag 作为查询参数传过去。

3. **tag 搜索后手动删除搜索框内容，筛选状态没有完全清除**  
   从详情页点击 tag 后，页面内部同时保存了 `keyword` 和 `tag`。如果只是手动删除搜索框文字，原来的 `tag` 条件仍然存在，所以看起来已经清空搜索，实际后端仍在按 tag 筛选。后来在输入框的 `input` 事件中增加判断：如果关键词为空，或者用户把关键词改成了其他内容，就清空内部 tag 状态。

4. **普通搜索无法搜到只包含对应 tag 的帖子**  
   测试时发现搜索“经验分享”时，如果帖子标题和正文不包含这个词，只是 tag 里有“经验分享”，普通搜索不会返回该帖子。解决时修改后端查询条件，让 keyword 同时模糊匹配 `posts.title`、`posts.content` 和 `tags.name`。
