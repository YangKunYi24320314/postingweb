## 遇到的问题与解决
1. **重复点赞和重复收藏问题**  
   点赞、收藏这类功能不能允许同一个用户对同一篇帖子重复操作。解决时没有只依赖前端按钮状态，而是在数据库表中使用唯一约束，例如 `post_likes` 的 `user_id + post_id`、`favorites` 的 `user_id + post_id`、`comment_likes` 的 `user_id + comment_id`。后端插入时使用 `ON CONFLICT DO NOTHING`，如果已经存在记录，就返回冲突提示，避免重复计数。

2. **计数字段与关系表的一致性问题**  
   点赞和收藏既需要在关系表中保存“谁点赞了什么”，又需要在 `posts.like_count`、`posts.favorite_count`、`comments.like_count` 中维护数量。为避免只插入关系表但忘记更新计数，后端把插入/删除关系记录和更新计数字段放在同一个事务中处理。这样如果其中一步失败，数据库可以回滚，减少数据不一致。

3. **取消点赞时计数不能变成负数**  
   如果用户重复请求取消点赞，理论上不能让 `like_count` 一直减到负数。解决方式是在 SQL 中使用 `GREATEST(count - 1, 0)`，保证点赞数、收藏数最低为 0。

4. **互动模块和评论模块边界容易混淆**  
   一开始容易把评论列表、发表评论也放进互动模块，但根据项目 API 文档，评论发布属于评论模块，互动模块主要负责点赞、收藏、评论点赞等动作。后来将分工边界调整为：本模块只实现互动动作，不负责评论内容的增删改查。

5. **前端页面归属问题**  
   最初为了测试按钮效果，曾临时把测试 UI 放到帖子广场页面中。但这样会影响其他同学负责的页面开发。后来改为封装 `InteractionButtons` 组件，并只短暂建立临时测试页验证效果，测试完成后删除测试页，保留可复用组件，避免破坏团队分工。
